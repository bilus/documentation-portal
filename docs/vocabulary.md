# Vocabulary

Terms of docportal, one per line.

- docportal: the program built from cmd/docportal.
- API spec: an OpenAPI 3.0 or 3.1 document in YAML with a non-empty info.title, usually a bundle.
- bundle: an API spec whose $refs all point inside its own file, such as #/components/schemas/Pet.
- sample bundle: testdata/specs/petstore-3.0.yaml or testdata/specs/petstore-3.1.yaml, the bundles the tests render.
- operation: one method on one path of an API spec, such as GET /pets/{petId}.
- model: a schema under components/schemas, as Stoplight Elements lists and opens it.
- operator: the person who starts docportal and gives it its configuration.
- reader: the person who reads the documentation in a browser.
- arguments: docportal's command-line arguments, without the program name: the flags and nothing else.
- flags: -addr, -config, -root, -refresh, -max-size, -previews, -preview-idle, -max-previews, -hide-try-it, -chat-model, -oidc-issuer, -oidc-client-id, -oidc-callback-url, -oidc-logout-url, -oidc-scopes, -oidc-audience and -session-lifetime. docportal refuses any other flag.
- environment: a lookup of environment variables, of which docportal reads DOCPORTAL_ADDR, DOCPORTAL_CONFIG, DOCPORTAL_ROOT, DOCPORTAL_REFRESH, DOCPORTAL_MAX_SIZE, DOCPORTAL_PREVIEWS, DOCPORTAL_PREVIEW_IDLE, DOCPORTAL_MAX_PREVIEWS, DOCPORTAL_HIDE_TRY_IT, DOCPORTAL_CHAT_MODEL, DOCPORTAL_OIDC_ISSUER, DOCPORTAL_OIDC_CLIENT_ID, DOCPORTAL_OIDC_CLIENT_SECRET, DOCPORTAL_OIDC_CALLBACK_URL, DOCPORTAL_OIDC_LOGOUT_URL, DOCPORTAL_OIDC_SCOPES, DOCPORTAL_OIDC_AUDIENCE, DOCPORTAL_SESSION_LIFETIME and DOCPORTAL_SESSION_KEY. The client secret and the session key come from it alone. Tests pass their own lookup.
- configuration: the address, the configuration file name, the bucket folder URL, the refresh interval, the size limit, the previews location, the idle time, the preview limit, the Try It setting, the chat model and the sign-in settings, each taken from its flag, else from the environment, else from its default: :8080, environment.yaml, empty, one minute, 256 MiB, empty, one hour, 10, false, empty and none. The client secret and the session key come from the environment alone.
- startup: reading the configuration, opening the documentation source, loading its snapshot, reading the portal configuration from the configuration file, adding the Try It setting, with an issuer signin.AccountLinks as the account hook, and the chat's routes to it, building the portal handler, starting the reloader, opening the previews location, wrapping the reloader in the previews handler, making the sign-in configuration, and with an issuer wrapping the previews handler in the sign-in middleware, in main.startup. A failure there stops docportal before its first request.
- address: the network address docportal listens on, such as :8080.
- documentation root: the directory that holds the configuration file and the files of the portals' sections. docportal's is a local directory or a bucket folder; an embedding program may pass any fs.FS.
- configuration file: a YAML file of the documentation root that lists the portals under portals:, each with name, sections and optional labels, and each section with title, type, input, optional labels and, for a docs section, toc. docportal reads the one that -config or DOCPORTAL_CONFIG names, environment.yaml by default.
- configuration file name: the configuration file's path as the operator gives it with -config or DOCPORTAL_CONFIG: on the local file system without a bucket folder URL, and inside the bucket folder with one.
- configuration file path: the configuration file's path inside the documentation root: the last element of the configuration file name for a local directory, and the whole name for a bucket folder.
- portal: a named set of sections in the portal configuration, whose pages have URLs of their own under /portals/{portal slug}/, with a chat page when the portal configuration's Chat serves one.
- portal name: a portal's name, the text of its link on the home page and in the portal menu.
- portal slug: a portal's name made into a slug by the rule of section slugs, such as delivery-api for Delivery API. It names the portal in its URLs, and no two portals share one.
- portal menu: the menu on the right of the navigation bar, before the account links, with two or more visible portals: the name of the page's portal, which opens a list of links to the first visible section of every visible portal, in the order of the portal configuration.
- home page: the HTML page at / with two or more visible portals, titled Portals, which links the first visible section of each visible portal under its portal name. With one visible portal, / redirects to that portal's first visible section, and with none, the home page holds the message No portals are open to you. With account links, the home page starts with a navigation bar that holds them alone.
- section: a spec or a content directory of the documentation root in a portal, shown under its title in the navigation bar of the portal's pages: a spec section or a docs section. Its input, and a docs section's toc path, are paths inside the documentation root, and a leading ./ and a trailing / are cleaned.
- section slug: a section's title in lower case, with each run of characters other than letters and digits as one dash and no dash at either end, such as getting-started for Getting Started. It names the section in its URLs, and no two sections of one portal share one.
- spec section: a section of type spec, whose input is a spec path.
- docs section: a section of type docs, whose input is a content directory path, with an optional toc path.
- sample configuration: testdata/environment.yaml, the configuration file of docportal's tests, with one portal, Petstore, which holds a spec section for testdata/specs/petstore-3.1.yaml and a docs section for testdata/docs.
- documentation root name: a local documentation root's path on the local file system: the directory of the configuration file name.
- documentation root handle: the documentation root as an fs.FS: a local directory opened with os.OpenRoot, which keeps each read inside the root, symlinks included, or a snapshot's files in memory. Every read of the configuration file, a spec, a markdown file or an image goes through it.
- documentation source: where the documentation root's files come from: a local directory, read live, or a bucket folder, read into snapshots. source.Source lists it and reads a listing's files.
- bucket folder: the objects of a bucket, on GCS, S3 or the local file system, whose keys start with an optional prefix, which ends in a slash: the documentation source that -root names by a Go CDK URL, such as gs://docs?prefix=portal/. Its listing's keys are the objects' keys without the prefix, so the configuration file path and the sections' inputs are relative to the folder. With a previews location, the documentation source is the bucket folder without it. source.Bucket reads it with Go CDK's blob package, with read access alone, and also reads a folder inside it as a source of its own (Bucket.Folder) and leaves a folder out of its listing (Bucket.Without).
- Go CDK URL: a URL that names a bucket to Go CDK's blob package, with the driver's scheme, the bucket's name and query parameters, of which prefix selects the bucket folder: gs://docs?prefix=portal/, s3://docs?region=eu-west-1&prefix=portal/ or file:///srv/docs?prefix=portal/.
- driver: Go CDK's support for one URL scheme, registered by a blank import of its package: docportal registers gcsblob, s3blob and fileblob, and an embedding program registers the drivers it needs.
- bucket folder URL: the Go CDK URL of the bucket folder, from -root or DOCPORTAL_ROOT, and empty by default, which makes the directory of the configuration file name the documentation source.
- listing: the objects of a documentation source at one check, each with its key, size, modification time and MD5 sum as the bucket reports them, in key order. It leaves out the zero-byte objects whose keys end in a slash, and the objects of a folder left out of the source, such as the previews location; a key that is not a valid io/fs path refuses the whole listing. A local directory's listing is empty.
- check: one listing of the documentation source by the reloader, every refresh interval, compared with the listing of the snapshot in service and with the last check's.
- refresh: the reloader's work on a settled change: reading the new snapshot, building its portal handler with the reloader's builder, and swapping it in.
- snapshot: a documentation source read at one time: a documentation root handle and the listing it was read from. A bucket folder's snapshot holds every object's bytes in memory; a local directory's is its documentation root handle.
- size limit: the largest total size of a listing's objects that the portal reads into a snapshot, from -max-size or DOCPORTAL_MAX_SIZE in MiB, 256 by default. A bucket folder over it refuses the snapshot. Zero means no limit.
- refresh interval: how often the reloader checks the documentation source, from -refresh or DOCPORTAL_REFRESH as a Go duration, one minute by default. Zero turns the checks off.
- settled change: a listing of the documentation source that differs from the snapshot in service and that two checks in a row report alike. Only a settled change becomes a new snapshot, so that an upload in progress, whose listing changes from check to check, is not loaded half done.
- builder: a function that builds the portal handler from a snapshot's documentation root handle: in docportal, the build method of main.builder, which reads the portal configuration, adds the Try It setting, with an issuer signin.AccountLinks as the account hook, and the chat, and calls portal.New, like startup's boxes, and keeps the chat across the builds; for a preview folder, the preview builder.
- reloader: the HTTP handler that source.NewReloader returns: it answers each request with the portal handler of the snapshot in service, checks the documentation source every refresh interval, and for each settled change builds the portal handler of the new snapshot with its builder and swaps it in, in one step. A check or a refresh that fails keeps the snapshot in service and writes the cause to the log. Each preview folder in memory has one too.
- snapshot in service: the snapshot whose portal handler the reloader answers requests with, kept with its listing. A request that started on it finishes on it after a swap.
- previews location: a folder of the bucket folder, such as previews, by its path inside the bucket folder, named by -previews or DOCPORTAL_PREVIEWS and empty by default, which turns previews off. The listing of the published documentation leaves it out, and each folder under it is a preview folder.
- preview folder: a folder of the previews location, such as previews/pr-123, which a CI job fills with the documentation of a pull request, read like a bucket folder, with a configuration file at the configuration file path, the size limit and the refresh interval of the bucket folder. Its name is one path segment of ASCII letters, digits, ., _ and -, other than . and .., so that it fits a cookie. A preview folder without objects or without a configuration file is missing.
- published documentation: the documentation of the bucket folder without its previews location, or of the local directory, as the reloader serves it, to every reader outside a preview.
- preview: the documentation of one preview folder, as a reader sees it after a switch at /previews/{folder} or /previews/{folder}/{path...}: every page, raw file and raw spec from the folder's snapshot, and the Elements assets of docportal, through the folder's portal handler, privately, with the banner on every page and without the chat.
- preview builder: the buildPreview method of main.builder, which builds a preview folder's portal handler from its snapshot like the builder, without the chat.
- preview snapshots: source.Previews, the snapshots of the preview folders in memory, each with its portal handler and a reloader of its own. Previews.Handler loads a folder's snapshot at the folder's first request, once for all of the folder's requests, and a check that finds the folder empty drops it, as do the idle time and the preview limit; a failed load of a folder with objects stays remembered for the refresh interval.
- idle time: the time after which an unused preview's snapshot leaves memory, from -preview-idle or DOCPORTAL_PREVIEW_IDLE as a Go duration, one hour by default. Zero means never.
- preview limit: the largest number of preview snapshots in memory, from -max-previews or DOCPORTAL_MAX_PREVIEWS, 10 by default. Zero means no limit.
- previews configuration: portal.PreviewsConfig: Open, which returns the portal handler of a preview folder by its name, loaded at the folder's first request, and the access hook. docportal's Open is Previews.Handler, and without an Open previews are off.
- previews handler: the HTTP handler that portal.WithPreviews returns around the published portal handler, in docportal the reloader: at /previews/{folder} and /previews/{folder}/{path...} it switches the reader to the preview of the folder, at /previews/ the reader leaves the preview, and it sends every other request to the portal handler of the reader's preview or to the published portal handler.
- preview request: portal.previewRequest, what one request asks of the previews handler: to leave the preview at /previews/, to switch to the folder named in a longer /previews/ path with the path to open after the switch, the reader's preview from the preview cookie, and an ended preview from the notice cookie.
- preview cookie: the cookie portal-preview, which holds the folder name of the reader's preview: a session cookie with the path /, set at a switch to a preview and cleared when the reader leaves it or it ends.
- banner: the line above the navigation bar of a page: on every page of a preview, the preview folder's name and a link out of the preview, to /previews/; on the first page of the published documentation after an ended preview, the notice.
- notice: the banner after an ended preview: The preview pr-123 is no longer available. This is the published documentation.
- notice cookie: the cookie portal-preview-ended, which holds the folder of an ended preview past a response that is no page, such as a redirect or a raw file: a session cookie with the path /, which the first page with the notice clears.
- ended preview: the reader's preview after its folder stopped opening for the reader: a deleted or missing folder, a folder hidden from the reader, or a failed load. The previews handler clears the preview cookie and sends the reader's request to the published portal handler with the notice.
- preview access: portal.PreviewAccess, an access with a third answer: Preview(folder) reports whether its reader may open the preview of a folder. With an access hook, a reader opens a preview only through a preview access that allows it; portal.Everything allows every preview.
- spec path: a spec section's input: the path, relative to the documentation root, of an API spec to serve.
- configured spec: the file at a spec section's spec path. Under a portal's /specs/ and /api/specs/, the portal handler serves no other file of the documentation root.
- missing spec: a request under a portal's /specs/ or /api/specs/ that names no configured spec: a slug of no spec section, or a spec section whose spec path has no file behind it. It gets a 404 that names the slug or the spec path.
- invalid spec: a configured spec that is not an API spec: not YAML, not OpenAPI 3.0 or 3.1, or without a title. It gets an error page naming the file and the reason, and its raw spec URL answers with an error naming the file and the reason, both with status 422.
- error page: the HTML page the portal handler shows instead of the viewer page for an invalid or missing spec, instead of a document page for a path that names no markdown file, or a hidden one, for a portal slug of no portal visible to the reader, and for a /previews/{folder} or /previews/{folder}/{path...} request that reaches it, with the title Preview not found and the folder's name.
- content directory: the directory of a docs section, at its content directory path, which holds markdown files and their images.
- content directory path: a docs section's input: its content directory's path inside the documentation root. No part of it may be a symlink.
- toc path: a docs section's toc: its toc file's path inside the documentation root, or empty, which leaves the section's document sidebar as #13 draws it. A spec section has none.
- toc file: a JSON file in the form of Stoplight's toc.json: {"items": [...]}, each entry an item with a title and a uri, a group with a title and entries of its own, or a divider with a title. A uri resolves against the documentation root, or is an http or https URL.
- content directory handle: a content directory as an fs.FS, which portal.New opens through the documentation root handle. The portal handler follows no symlink in it.
- markdown file: a regular file of a content directory named *.md or *.markdown, reached through no symlink.
- image: a regular file of a content directory named *.png, *.jpg, *.jpeg, *.gif, *.webp or *.svg, reached through no symlink.
- hidden: of a file or directory of a content directory, with a name that starts with a dot. The portal handler lists and serves nothing hidden and nothing inside a hidden directory. Distinct from hidden from the reader.
- path: in /portals/{portal slug}/docs/{section slug}/{path} and /portals/{portal slug}/raw/{section slug}/{path}, a slash-separated path relative to the section's content directory.
- sample documents: testdata/docs, the fixture directory of the markdown file and raw file tests.
- portal configuration: portal.Config: the documentation root handle, the portals, the Try It setting, the chat's routes, the access hook and the account hook, as portal.New takes them. An embedding program builds it in Go, or reads its portals from a configuration file with portal.ReadConfig. Tests pass any fs.FS in the handle's place.
- embedding program: a program other than docportal that mounts the portal handler, usually behind its sign-in middleware, through the embedding API.
- embedding API: the exported API of the packages portal, chat, source and signin, which an embedding program imports. It is not stable yet.
- core packages: portal, source, chat and anthropicmodel: they import neither package signin nor any OAuth or OpenID Connect library or identity provider's package, and make lint checks their imports.
- sign-in middleware: the middleware that sends each reader without a sign-in session through a sign-in and puts each signed-in reader's identity into the request's context, where the request hooks read it, before its wrapped handler answers: package signin's, around the previews handler in docportal with an issuer, or an embedding program's own, around its portal handler.
- sign-in: one run of the way into the portal for a reader without a sign-in session: the start, the identity provider's check of the reader, and the callback, which opens a new sign-in session.
- identity provider: the service that identifies the portal's readers: an OpenID Connect provider, such as Auth0, Okta, Google, Keycloak or Microsoft Entra ID, by its issuer, or an OAuth 2.0 provider without OpenID Connect, such as GitHub, through a Provider.
- issuer: the issuer URL of an OpenID Connect provider, such as https://TENANT.auth0.com/, from -oidc-issuer, DOCPORTAL_OIDC_ISSUER or signin.Config.Issuer, at which signin.New discovers the provider's endpoints. docportal's is empty by default, for no sign-in.
- sign-in settings: main.signInConfig: the issuer, the client ID, the client secret, the callback URL, the logout URL, the scopes, the API audience, the session lifetime and the session key, each from its flag, else from the environment, apart from the client secret and the session key, from the environment alone. docportal refuses any of them without an issuer.
- sign-in configuration: signin.Config: the identity provider, by its issuer or a Provider, the client ID and the client secret, the callback URL, the logout URL, the sign-out path, the scopes, the API audience, the session lifetime and the session key, as signin.New takes them. docportal makes it of the sign-in settings.
- Provider: signin.Provider: an OAuth 2.0 provider without OpenID Connect, such as GitHub, as an embedding program gives it: its endpoints, and the identity of the reader behind its tokens.
- identity: signin.Identity: a signed-in reader as the identity provider names them: the subject, the name, the email and the claims. signin.IdentityOf reads it from a request's context.
- claims: signin.Claims: the identity provider's statements about a reader, such as groups or roles, as JSON values: every claim of the ID token, or those of the Provider.
- subject: the identity provider's stable ID of a reader, unique within the provider: the sub claim of the ID token, or the Provider's. It is the reader ID of docportal's sign-in.
- ID token: the signed JWT of the reader's identity that an OpenID Connect provider returns with the tokens; the sign-in middleware checks its signature, its issuer, its audience, which must hold the client ID, its expiry and its nonce.
- sign-in session: one signed-in reader's stay, from the callback to its expiry or the reader's sign-out: a session ID, the identity and the expiry, kept in the session cookie. Distinct from the page session and from the chat's sessions.
- session cookie: the sealed cookie of the sign-in session: HttpOnly, SameSite=Lax and for /, and with an https callback URL Secure, as __Host-signin_session.
- session ID: a sign-in session's random ID, new at each sign-in; sign-out revokes it.
- session lifetime: the time from a sign-in session's start to its expiry, from -session-lifetime, DOCPORTAL_SESSION_LIFETIME or signin.Config.Lifetime, 8 hours by default.
- session key: the secret of 32 bytes or more behind the seal of the session cookie and the attempt cookie, from DOCPORTAL_SESSION_KEY or signin.Config.Key, the same for every replica. Without it, docportal makes a random one, so that the sign-in sessions last until docportal's exit.
- sealed: of a cookie's value, encrypted and authenticated with AES-256-GCM under a key from the session key and the callback URL, and bound to the cookie's name, so that the browser can neither read nor change it, and no other portal or cookie can pass it off as its own.
- sign-in attempt: the attempt cookie's record of one sign-in: the state, the nonce, the PKCE verifier and the return target, for ten minutes.
- attempt cookie: the sealed cookie of a sign-in attempt, for the callback path alone, deleted at the callback.
- state: a random value of the sign-in attempt, in the authorization request and again in the callback, which must match the attempt's, so that each callback belongs to an attempt of its browser. Distinct from the state of a chat page.
- nonce: a random value of the sign-in attempt for the ID token to carry, so that each ID token belongs to its attempt.
- PKCE: Proof Key for Code Exchange with S256: the authorization request carries the hash of the attempt's random verifier, and the code exchange the verifier itself, so that a stolen code is worthless.
- return target: the path and query of the request at the sign-in's start, the callback's destination for the reader: a relative path on the portal's own origin, else /.
- callback URL: the portal's URL for the identity provider's answer, as registered at the provider, such as https://docs.example.com/auth/callback, from -oidc-callback-url, DOCPORTAL_OIDC_CALLBACK_URL or signin.Config.CallbackURL; the middleware answers its path.
- callback: the request to the callback URL's path with the code and the state, at which the sign-in ends with a new sign-in session or the sign-in error page.
- sign-out path: the sign-in middleware's route for sign-out, /auth/sign-out by default, and the URL of the sign-out link among the account links.
- sign-out: a reader's request to the sign-out path, which ends the reader's sign-in session.
- logout URL: the reader's destination after a sign-out, such as the identity provider's logout endpoint, which ends the provider's session too; without one, the signed-out page.
- signed-out page: the middleware's page after a sign-out without a logout URL, with a link to sign in again.
- sign-in error page: the middleware's page after a failed or cancelled sign-in, with a link to the return target for a retry; it grants no access.
- revoked sessions: the session IDs of the sign-in sessions that a sign-out ended before their expiry, each kept until that expiry in the middleware's memory; the middleware refuses their cookies.
- client secret: the portal's secret as an OAuth client at the identity provider, from DOCPORTAL_OIDC_CLIENT_SECRET alone or signin.Config.ClientSecret; the sign-in middleware sends it to the token endpoint alone, and it appears in no log line, no response and no URL of the browser.
- client ID: the portal's ID as an OAuth client at the identity provider, from -oidc-client-id, DOCPORTAL_OIDC_CLIENT_ID or signin.Config.ClientID. Distinct from a client of the chat.
- scopes: the scopes of the authorization request, from -oidc-scopes, DOCPORTAL_OIDC_SCOPES or signin.Config.Scopes: openid, profile and email by default, with openid first for an issuer.
- API audience: signin.Config.Audience, from -oidc-audience or DOCPORTAL_OIDC_AUDIENCE: an optional parameter of the authorization request, as Auth0 takes it for its APIs. Distinct from the ID token's audience, which must hold the client ID.
- tokens: the identity provider's answer to the code at its token endpoint: the access token, and from an OpenID Connect provider the ID token.
- code: the authorization code of a sign-in, from the identity provider to the callback, for the tokens at the token endpoint.
- authorization URL: the identity provider's authorization endpoint with the sign-in attempt's state, nonce and PKCE challenge: the start's redirect for the reader.
- provider metadata: an OpenID Connect provider's discovery document at its issuer, with its endpoints.
- signing keys: an OpenID Connect provider's public keys for the signatures of its ID tokens.
- access hook: portal.Config.Access, and portal.PreviewsConfig.Access for the previews handler, a request hook: it returns the access of the request's reader, or an error. An error, or a nil access with no error, hides everything from the reader and goes to the log.
- access: portal.Access: two answers for one reader: Portal(p) and Section(p, s) report whether the access allows a portal and a section, each as the portal configuration gives it, labels included. The access hook returns one for each request, and the page access is one too. portal.Everything allows every portal and section, and every preview as a preview access, and is every reader's access without an access hook.
- labels: an optional list of strings on a portal or a section, under labels: in the configuration file or in the Go fields of portal.Portal and portal.Section, for the rules of the access hook. The portal handler does not use them.
- visible: of a section, allowed by the reader's access, in a portal allowed by the access; of a portal, allowed by the reader's access, with at least one visible section.
- hidden from the reader: of a portal or a section, not visible to the reader. It answers on every route as a missing one, and links and toc entries to its pages lead nowhere. Of a preview folder, not allowed by the reader's preview access: a switch to it answers as one to a missing folder. Distinct from hidden, of a file.
- reader's sites: the sites of the portals visible to one request's reader, each a copy of its portal's site with only its visible sections.
- reader's view: portal.view: the access and the account links of one request's reader, and the reader's sites, as the router builds them for the request and passes them to its pages.
- page access: the access that a chat tab keeps from its GET: everything for a reader whose access is portal.Everything, else the titles of the sections visible to its reader, by portal, each portal with a digest of its configuration, which closes the portal to the page after a change of it. live-templ signs it into the page session, and the page's mount at the join and each of the page's questions read it from there.
- live-templ: the module of live pages, github.com/bilus/live-templ, that serves the chat page: it renders the page at its GET, and runs it over the page's socket after the join.
- page session: the values that live-templ signs into a chat tab at its GET, from chat.Chat.sessionOf, and gives back at the join: the client, the reader ID, in base64 so that every byte of it survives the signer's JSON, the page access and the account links. Signing does not encrypt them, so the reader's browser can read them. Distinct from the chat's sessions, which hold its conversations, and from the sign-in session.
- chat tab: a chat page as one GET loads it into the reader's browser: its page session, its socket and its conversation.
- conversation: the questions and answers of one chat tab, kept in a session of the chat, with a separate history for each set of visible sections that its questions read.
- join: a loaded chat page's first message over its socket, at which live-templ mounts the page again from its page session, with no request.
- mount: chat.Chat.mount, which builds the state of a chat page from its page session, at the page's GET and again at the join.
- stub hook: fakeaccess.Hook of internal/fakeaccess, the access hook of the tests: it reads the sections visible to the reader from the request's Sections header, each as portal name/section title, and the preview folders open to the reader from its Previews header.
- client: the IPv4 address, or the IPv6 /64 network, of a chat page's request, as clientOf names it. A client is not a reader: every reader behind one proxy is one client.
- request hook: an optional function of the request in portal.Config.Access, portal.Config.Account or chat.Config.Reader, which names the request's reader to the portal or the chat, such as from what a sign-in middleware put into the request's context: the access hook, the account hook and the reader hook. The portal handler calls its hooks once for each request, the previews handler calls its access hook once for each request with a folder to switch to or a preview to serve, and the chat asks the reader hook at a chat page's GET. With an issuer, docportal sets the account hook to signin.AccountLinks and, with a chat model, the reader hook to signin.ReaderID.
- account hook: portal.Config.Account, a request hook: it returns the account links of the request's reader. The portal handler calls it once for each request.
- account links: the portal.AccountLink values that the account hook returns, such as the reader's name and a sign-out link, each a link text with a URL, or a link text alone, which shows as text. They end every navigation bar of the request's pages, and a chat tab keeps those of its GET.
- reader hook: chat.Config.Reader, a request hook: it returns the reader ID of the request's reader, or an empty string for a reader who is not signed in. The chat asks it at a chat page's GET.
- reader ID: the non-empty string that the reader hook returns for a reader, the same from every client, such as the subject of the reader's identity, as signin.ReaderID gives it. A reader with a reader ID is signed in.
- asker: chat.Asker, what the question limit counts a question against, as chat.AskerOf makes it from a reader ID and a client: the signed-in reader of the reader ID, from any client, or for an empty reader ID, the client, each in a namespace of its own, so that a reader ID never shares an asker with a client, even with the same text. A chat tab asks as the asker of its page session's reader ID and client, and Chat.Ask takes the asker with each question and refuses the zero Asker, which names nobody.
- question limit: the chat's bound on the questions of one asker, Limits.Questions in Limits.Window, 20 an hour by default, in all portals together.
- question counts: the times of each asker's questions in the window, which the chat keeps across snapshots, and against which the question limit counts each new question.
- portal handler: the HTTP handler that portal.New returns: it redirects / to the first visible section of the only visible portal or serves the home page, serves the pages of each visible portal under /portals/{portal slug}/, each visible spec section's viewer page and raw spec and each visible docs section's document list, document pages and raw files, serves the Elements assets, and answers /previews/{folder} and /previews/{folder}/{path...} with an error page. With an access hook or an account hook, every response is private.
- private: of a response, carrying Cache-Control: private, so that no shared cache gives it to another reader. portal.Private, the private handler, wraps a handler so that each of its responses is private, even when the handler deletes the header. The previews handler sends every response at a /previews/ path, every response in a preview and every response with the notice privately.
- site: a portal after openPortals has checked it, with its sections opened, and with the configured portal and sections for the access hook, as the router serves its pages.
- router: portal.router: the portal handler as a Go value, built by newRouter: the routes, the sites, the access hook and the account hook. Its ServeHTTP answers each request with the reader's view.
- HTTP server: net/http's server, which listens on the address and calls startup's handler for each request: the previews handler, the reloader itself without a previews location, behind the sign-in middleware with an issuer.
- viewer page: the HTML page at /portals/{portal slug}/specs/{section slug} that embeds Stoplight Elements pointed at a spec section's raw spec, with the Try It console unless the Try It setting hides it.
- Try It console: the part of the viewer page where Stoplight Elements sends requests from the reader's browser to the servers listed in the raw spec.
- Try It setting: whether the viewer page hides the Try It console. It is true with -hide-try-it or a true DOCPORTAL_HIDE_TRY_IT, and false by default.
- document list: the HTML page at /portals/{portal slug}/docs/{section slug}/, under the section's title. With the section's toc path, it shows the toc file's entries as the document sidebar does, with a heading for each group and divider, and then, under the heading Other documents, a link to the document page of each markdown file of the section without an entry. Without a toc path, or while the toc file is missing or invalid, it links the document page of every markdown file of the section. Either way, it leaves out hidden files, and a link to a file outside the entries has the file's path as its title, in byte order of the paths.
- document page: the HTML page at /portals/{portal slug}/docs/{section slug}/{path} that shows one markdown file of a docs section rendered as HTML without active content, with each relative link pointed at the page that serves its link target, or shown as text when the link leads nowhere.
- relative link: a markdown link, inline or by reference, whose destination has a path but no scheme and no host, such as docs/guide-oauth.md or /docs/guide-oauth.md. An <a> element in raw HTML is not one.
- link target: the path named by a relative link, taken against the documentation root or, when no page serves that and the link has no leading /, against the markdown file's directory. It may leave the documentation root. A link target is served within the portal of the link's markdown file: a markdown file by the document page of the docs section that shows the link, when its content directory holds the file, else by that of the portal's first visible docs section that holds it, and a configured spec and its parts by the viewer page of the portal's first visible spec section whose spec path names it.
- Stoplight: a hosted documentation platform, the target of the guides in conrad-api-docs. It resolves a relative link against its project root, the top directory of the repository.
- Stoplight operation link: a relative link to <spec path>/paths/<path>/<method>, with the path escaped as in a JSON pointer, as Stoplight writes a link to an operation, such as CONRAD-Delivery-API.oas2.yml/paths/~1devices/post. The part after <spec path>/ is its pointer: a JSON pointer into the spec without its leading /.
- operation route: the part of a viewer page URL after the #, which opens one operation: /operations/{operationId}, or /paths/{slug}/{method} for an operation without an operationId. The slug is the operation's path with each /, {, } and space turned into -, the first run of dashes collapsed to one and a dash trimmed from each end, as Stoplight Elements makes it.
- leads nowhere: of a relative link, shown as its text alone, without the link, because no page visible to the reader serves its link target, the target leaves the documentation root, or the destination does not parse.
- document sidebar: the column at the left of a docs section's document list and document pages, under the section's title. With the section's toc path, it shows the toc file's entries that a page visible to the reader serves; without one, or while the toc file is missing or invalid, it links the document page of every markdown file of the section that is not hidden, grouped by directory. It has the markup and the classes of the sidebar that Stoplight Elements draws on the viewer page.
- active content: markup that runs in the reader's browser, such as a <script> element or a javascript: link.
- navigation bar: the links at the top of every HTML page of a portal: to the page of each of its visible sections under the section's title, in the order of the portal configuration, to its chat page when the portal configuration's Chat serves one, with two or more visible portals the portal menu, and at its right end the account links. The 404 page of a missing portal has a bar with one link, Portals, to the home page, and the account links; the home page has a bar with the account links alone, when there are any.
- chat page: the live page at /portals/{portal slug}/chat where a reader asks questions about the APIs of the portal's visible spec sections, each named in its heading, and the chat model answers through read-only tools from the published specs and the markdown files of the sections of the portal allowed by the page access. The portal handler serves it only when the portal configuration's Chat holds the chat's routes, as docportal's does when a chat model is named, and one chat serves the chat pages of every portal. It is private as every response of the portal handler is, and with a reader hook.
- chat model: the Anthropic model that answers on the chat page, named by -chat-model or DOCPORTAL_CHAT_MODEL, and empty by default, which leaves the chat off.
- chat: chat.Chat, the one answerer behind the chat pages of every portal, built with the chat model for the first snapshot and given each new snapshot's libraries with Chat.Reload, which keeps its sessions, conversations and question counts. A snapshot that fails leaves it as it is.
- library: portal.Library, the documentation of a portal as the chat reads it: the published spec of each of its spec sections, its operations and parts, and the text of the document page of each markdown file that a document list shows, each with its page's URL. Library.For limits it to the sections visible to one reader.
- published spec: the configured spec without its unpublished parts and marker keys. The raw spec carries it, and the viewer page's title and the operation routes come from it.
- raw spec: the response at /portals/{portal slug}/api/specs/{section slug}, as application/yaml: the configured spec without its unpublished parts and marker keys. A configured spec from which the rules remove nothing comes back byte for byte. Any other spec is written again from its parsed form, with every YAML document and the order of its keys, but not its layout.
- unpublished part: a part of the configured spec that a marker key marks for the publication target main: a key whose value is a mapping with an x-doNotPublish value that names main, together with that mapping; a list element that is such a mapping; or the sibling <name> of a key x-doNotPublish-<name> whose value names main. A value names main when it is the scalar main or a list that holds main. The root mapping is never an unpublished part, and an alias counts as a copy of its anchor's node.
- marker key: an x-doNotPublish key or a key x-doNotPublish-<name>. Its value names one or more publication targets.
- publication target: a name in the value of a marker key, such as main or beta, for one publication of the documentation. docportal publishes for main alone.
- raw file: the response at /portals/{portal slug}/raw/{section slug}/{path}: an image that is not hidden, unchanged, with the image type of its extension, X-Content-Type-Options: nosniff, so that the browser reads it as that type only, and Content-Security-Policy: sandbox, so that no script in it runs.
- Stoplight Elements: the web component that renders an API spec as documentation in the reader's browser.
- Elements assets: the Stoplight Elements script, stylesheet and license, downloaded by `make setup` and embedded in docportal.
